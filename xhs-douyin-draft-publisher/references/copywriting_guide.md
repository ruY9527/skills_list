# 图文文案、标签与图片准备规范

## 1. 素材读取与真实性约束

### 场景 A：用户提供本地图片（如宣传卡片、截图）
- 必须先逐张读取图片内容，**绝不编造图片中未出现的功能、数据或项目名**。
- 若当前模型无原生视觉能力，使用 `rapidocr_onnxruntime` 离线提取文字（官方 PyPI 若 SSL 报错，使用清华源）：
  ```powershell
  pip install -i https://pypi.tuna.tsinghua.edu.cn/simple rapidocr-onnxruntime
  ```
- **编码注意**：Windows PowerShell 默认 GBK，OCR 提取结果务必以 `encoding="utf-8"` 写入临时 `.txt` 文件后再读取，避免中文乱码。

### 场景 B：用户提供关键词或开源项目仓库
- 先核查真实仓库信息（核心功能、UI 结构、测试数量、实测指标、许可证与 GitHub 地址），所有数据必须可验证。
- 如需用 Python（Pillow）程序化生成推广图：
  - 尺寸：**3:4 竖版（1080×1440）**。
  - 字体：Windows 下使用 `微软雅黑`（`msyh.ttc` / `msyhbd.ttc`），避免等宽英文字体导致中文显示方块。
  - 排版：卡片高度按实际文本测量动态计算；换行逻辑禁止把英文单词拦腰截断，禁止中文标点出现在行首。
  - 图片顺序：严格按叙事逻辑排列（如 `01封面痛点 → 02界面展示 → 03核心功能 → 04量化数据对比 → 05安装与项目地址`），最具信任背书的数据图不要放在最后一张。

## 2. 平台字数与内容适配

| 字段 | 小红书 | 抖音 | 适配要点 |
| :--- | :--- | :--- | :--- |
| **标题** | ≤ 20 字（建议 ≤ 18 字） | ≤ 20 字（建议 12–16 字） | 抖音更短、更口语化，去掉 `《》`、`—` 等装饰符号 |
| **正文 / 描述** | 总计 ≤ 1000 字（含标签） | 总计 ≤ 1000 字（含话题） | 正文严格控制在 **≤ 950 字**，为 4 个标签预留 ~32–50 字符 |
| **标签 / 话题** | 前 3–5 个决定初始流量池 | 话题命中流量池更容易 | 自动化草稿默认填 **4 个高精准标签**；人工精修时小红书最多可配至 20 个 |
| **图片数** | ≤ 18 张 | ≤ 35 张 | 优先 3:4 竖版高清 PNG |

## 3. 标题公式（5 种高频模板）

核心原则：**具体收益 + 情绪钩子**，杜绝「分享一个」「值得收藏」等空泛词。

1. **情绪 / 结果型（主推）**：`公众号好文，一键变成能存一辈子的文件`
2. **故事 / 动机型（涨评论）**：`收藏的文章都会烂，所以我写了个导出工具`
3. **搜索关键词型（吃长尾）**：`公众号文章转 Markdown，图也一起打包`
4. **痛点直击型（高点击）**：`别再截图存公众号了，这一步直接存成文件`
5. **人设 / 轻叙事型**：`一个免费开源的小扩展，治好了我的收藏焦虑`

抖音版压缩示例：
- `公众号好文一键存成文件`（11 字）
- `科研人必存：20个本地技能`（13 字）

## 4. 正文结构模板

1. **前 3 行强钩子**（决定完播/展开率）：直击真实痛点或反常识结论（如「读研最累的，不是做实验，是不知道下一步该用什么工具」）。
2. **核心价值分点**：用 `① ② ③` 或 `①~④` 结构化拆解，每点「功能 + 真实场景」，短句分段留白。
3. **信任背书**：交代纯本地运行 / 开源免费 / 实测量化指标（如 `609.1pt → 27.2pt`、`68 项测试通过`），比空洞吹捧转化高得多。
4. **上手方式与项目地址**：简明 3 步使用说明 + 明文项目地址（注：小红书正文外链不可点击，建议同时准备简介与置顶评论文本）。
5. **互动收尾**：用开放式提问或「点个 star 就是最好的支持」替代违规诱导词。

## 5. 标签策略与合规红线

- **标签组合**：**精准意图词（1–2 个）+ 垂类大流量词（2–3 个）**，例如：
  - 工具项目：`#公众号文章导出 #效率工具 #开源项目 #知识管理`
  - 科研技能：`#CodexSkills #科研工具 #研究生日常 #AI效率工具`
- **禁用泛标签**：不要用 `#好物推荐 #日常 #分享` 等超泛词，会把内容推给无关人群拉低点击率。
- **合规避坑**：
  - 严禁出现「求关注」「求点赞」「求三连」等诱导互动词（易触发限流）。
  - 48 小时内不要连续发布高度重复的工具推广内容（建议间隔 ≥ 5 天）。
  - 若需人工发布后维护，可顺带输出一份「置顶评论 FAQ」（覆盖安装方式、隐私安全、平台兼容性等高频问题）。
